# AGENTS.md — правила для AI-агентов

Правила работы с этим репозиторием. Коротко и обязательно.

## Перед работой

- **Сначала читать документацию**: README.md → docs/ARCHITECTURE.md →
  docs/HARDWARE.md → docs/UX.md → docs/COURSE_FORMAT.md. Это быстрее,
  чем восстанавливать контекст по коду.
- docs/TECHNICAL_PLAN.md — исторический документ (исследование);
  при расхождении с ним верь коду и ARCHITECTURE.md.
- **Перед крупными изменениями — сначала краткий план** (несколько
  строк: что, зачем, какие файлы), согласовать до кода.

## Код

- **Не менять архитектуру без причины.** Слои и порядок boot в
  main.cpp выстраданы на железе — любое изменение обосновывать.
- **Не добавлять функции без явного запроса.** Идеи — в ROADMAP.md,
  не в код.
- **Не переписывать работающие части ради красоты.** Рефакторинг
  только вместе с багом/задачей.
- **Не ломать hardware compatibility**: не хардкодить контроллер
  панели (партии SSD1677/UC8179/UC8279), не трогать порядок
  framebuffer-first / SD-before-display, не выходить за бюджет
  памяти (см. HARDWARE.md).
- **Учитывать ограничения e-ink**: без анимаций и миганий; движение =
  инверсия строки; текст листается страницами.
- **Избегать лишнего full refresh**: все обновления — FAST; полный кадр
  только на карточке выключения, по CLEAN SCREEN NOW, при смене
  ориентации/RESET и при включённом пользователем Auto Clean
  (по умолчанию выключен). Не возвращать автоматические FULL
  без запроса пользователя.
- **Четыре ориентации: 0°/90°/180°/270°** (см. UX.md). Буфер кадра
  всегда панельный 800×480 — второго framebuffer нет; поворот =
  трансформация координат в Canvas. Каждый экран верстается с
  отдельными метриками для портретных ориентаций (поля, высоты строк,
  лимиты переносов), а не растягиванием landscape.
- **Прошивка — только app0 @ 0x10000**: `pio upload` на этой плате
  перезаписывает ещё bootloader/partitions/otadata (проверено на
  железе) — шей прямым esptool из README и сверяй вывод: ровно одна
  запись `Wrote ... at 0x00010000`. Никогда `erase_flash`.
- **Соблюдать course format** (docs/COURSE_FORMAT.md): лимиты
  config.h, стабильные id уроков/srs-итемов, типы упражнений.
- **Backward compatibility**: старые курсы и progress.json обязаны
  грузиться после изменений формата; неизвестные поля игнорировать.
- Домен (`course/`, `srs/`) остаётся без Arduino-типов — он
  тестируется на хосте.

## После изменений

- **Всегда собирать**: `pio run -e esp32c3` (0 ошибок; из venv
  `%USERPROFILE%\lingoink-venv\Scripts\pio.exe`, системный Python
  3.14 платформой не поддерживается). Прошивать из cmd/PowerShell,
  только app0 @ 0x10000, никогда `erase_flash`.
- **Задет UI (экраны/Canvas/Chrome/шрифты)** — прогнать host-превью:
  `bash tools/preview/run.sh` из корня (все экраны × 4 ориентации в
  `out/preview/*.png`; компилятор — g++ из `%USERPROFILE%\mingw64`,
  ставится на PATH скриптом сам). Вёрстка экранов — только через
  `src/ui/Chrome.h` и метрики `config.h`, без локальных магических чисел.
- Прогнать `pio test -e native`, если задет домен (нужен host g++;
  работает с `%USERPROFILE%\mingw64\bin` в PATH).
- **Обновлять документацию при изменении архитектуры/поведения** —
  docs/, при новых ограничениях формата — COURSE_FORMAT.md.
- Крупные поведения (refresh, питание, формат) сначала проверять по
  чек-листу docs/HARDWARE_VALIDATION.md на реальном железе, если оно
  доступно.
- Не коммитить мусор: `.pio/`, `out/`, `backup/*.bin` вне репозитория.

## Красные линии

- GPL-код в дерево не вносится (см. LICENSE-NOTES.md).
- NVS/bootloader/partition table не стираются и не перешиваются.
- Wi-Fi/BLE включение в MVP — только по явному запросу.
